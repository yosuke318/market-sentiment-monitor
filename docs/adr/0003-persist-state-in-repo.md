# 0003. 前回状態をリポジトリにコミットして持つ

- ステータス: Accepted
- 日付: 2026-10-04

## 背景

区分の変化を検知するには前回の区分が必要。また週末・米国祝日は前営業日と同じデータが返るため、重複通知を避ける必要がある。

## 決定

`state/state.json` に前回の `rating` / `score` / `timestamp` を保存し、ワークフローの最後にコミット・プッシュする。今回の `timestamp` が保存値と同じなら通知せず終了する。

## 選ばなかった選択肢

- **状態を持たず API の `previous_close` から前日の区分を計算**: 前日の区分は API が返さないため境界値を自前で判定することになり、CNN の表示とずれうる（0001）。週末・祝日の重複通知も防げない
- **actions/cache に保存**: 7 日間アクセスがないと消える。キャッシュは消えてよいもの向けで、状態保存には向かない
- **外部 KV（Upstash 等）**: 値 3 つのためにアカウント・シークレットが増える

## 影響

- 営業日ごとに bot のコミットが 1 件増える。副次的に変化の履歴が git log に残る
- ローカル実行で作られた `state/state.json` をコミットすると Actions 側の状態を上書きしてしまう
